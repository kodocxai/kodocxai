# P17 실행 노트 - LiLT 1시드 시도 (2026-10-07, 실험세션)

발주(10-05, P17 v1): 대안 모델 LiLT 1시드로 결과 재현 여부 확인. 중단 규칙 3종
적용 항목(실패 허용). 이 노트는 사전 확인·진단·레시피 조정의 정직한 기록이다.

## 사전 확인 (중단 규칙 (i) 판정)

- 체크포인트 실재: `SCUT-DLVCLab/lilt-infoxlm-base` (Hugging Face, MIT 라이선스,
  0.3B 파라미터). InfoXLM = XLM-R 계열 다국어 어휘(250k)로 한국어 포함.
- 토크나이저: 리포가 LayoutXLM 토크나이저(boxes·word_labels 직접 수용)를 싣고
  있고, **같은 문서에 대한 input_ids가 LayoutXLM 정본 파이프라인과 완전 일치함을
  실측 확인**(diag4) - 서브워드 분절·어절 정렬 로직이 그대로 호환된다.
- 8GB 가능성: 시각 백본 없음(텍스트+레이아웃) - LayoutXLM보다 가볍다. 스모크
  통과, VRAM 여유. → **미착수 사유 없음, 착수.**

## 구성 (정본 재사용 원칙)

- `lilt_shim.py`: LayoutXLMProcessor 호출면 호환 심 - 이미지 인자 무시, 토크나이저
  위임. 정본 kodx_*.py 무수정.
- `train_lilt.py`: kodx_train.py 구조·하이퍼파라미터 복제(동일 데이터 5,000건·
  배치 1·누적 16·lr 5e-5·시드 절차). LiLT 는 gradient checkpointing 이 지원되어
  켜짐(LayoutXLM 은 미지원이라 꺼져 있었음 - 아래 진단에서 무관 판명).
- `run_eval_lilt.py`: kodx_data.load_processor 를 심으로 치환한 뒤 정본
  eval_kie·kodx_eval 의 main 을 그대로 호출 - 채점·집계 코드 경로 동일 보장.

## 1차 학습 실패와 진단 (10-07)

3에폭(정본 레시피 그대로) 학습 결과 **전 필드 F1 0.000 - 전부 "O" 예측으로
붕괴**(loss 2.28→0.66 정체). 원인 절연 과정:

| 가설 | 검사 | 결과 |
|---|---|---|
| 라벨 정렬 오류 | 어절·토큰 라벨 수 대조 | 정상(절단만 영향) |
| 토큰화 상이 | LayoutXLM 정본과 input_ids 대조 | **완전 일치** |
| 기울기 단절(checkpointing 등) | 전 층 grad norm 실측 | 전 층 정상 흐름 |
| AMP·8bit Adam·checkpointing | 전부 끄고 fp32 과적합(20건) | 여전히 정체 - 무관 |
| 좌표 위생 | x0≤x1·y0≤y1·0~1000 전수 | 위반 0 |
| bbox 자체가 유해 | bbox=0 대조 학습 | 동일 정체 - 무관 |
| 가중치 적재 실패 | output_loading_info | classifier 외 전부 적재 |
| 은닉 표현 퇴화 | 쌍별 cos 유사도 | 정상(0.43 - XLM-R보다 다양) |
| 모델 무관 루프 결함 | 같은 루프에 xlm-roberta-base | **XLM-R은 정상 하강** - LiLT 고유 |
| **수렴 지연(느린 탈출)** | 600스텝 장기 과적합 | **~500스텝 정체 후 하강 시작** ✓ |

결론: 구현·입력 결함이 아니라 **LiLT의 수렴 특성 - 다수 클래스 붕괴 고원이
길다**(동일 데이터에서 XLM-R 은 ~100스텝, LiLT 는 ~500~600스텝에 탈출). 정본
3에폭(약 937 갱신)은 고원 탈출 직전에서 끝난 것.

## 2차: 에폭 연장 시도 → 역시 미달 (10-07)

에폭 3→10 연장(이어하기, 그 외 동일): loss 0.66→0.51 완만 하강, **micro F1
0.056**(P 0.726 / R 0.029 - 개체 예측이 막 시작되는 단계). 고원 탈출이 수천
갱신 규모로 느려 에폭 연장만으로는 실용 수준 불가 판단.

## 3차: 원인 확정 - InfoXLM 텍스트 흐름 가중치 (10-07)

추가 절연 실험: LiLT의 텍스트 흐름 가중치를 xlm-roberta-base 로 치환(197/398
키, 레이아웃 흐름은 LiLT 사전학습 유지)하자 **같은 20건 과적합이 300스텝에
loss 0.03으로 정상 수렴**. 즉 수렴 지연의 원인은 구조가 아니라 **SCUT 공개
체크포인트의 InfoXLM 텍스트 흐름 가중치**다(이 과제·한국어 데이터에서 미세조정
출발점으로 부적합 - 원인 추정: 공동 사전학습 상태의 호환성 문제, 추정임을 명시).

## 4차: XLM-R 초기화 본학습도 붕괴 → 두 번째 독립 원인 (10-07)

--xlmr-init 본학습(3에폭) 역시 F1 0.000. 과적합 성공 환경과 본학습의 차이를
절연한 결과 **gradient checkpointing 이 단독 범인**으로 확정(20건 과적합 A/B:
켜면 200스텝에 loss 1.55 기다시피 하강, 끄면 0.10 정상 - transformers 4.57.6 의
LiLT checkpointing 경로가 최적화를 망가뜨림. LayoutXLM 정본 학습은 checkpointing
미지원이라 애초 꺼져 있었고, 과적합 진단 스크립트들도 전부 꺼서 이 변수가
가려져 있었다).

정리하면 독립 결함 2개의 중첩이었다:
  ① gradient checkpointing(HF LiLT 구현) → 끈다 (LayoutXLM 정본과도 정합)
  ② SCUT 체크포인트의 InfoXLM 텍스트 흐름 가중치 → xlm-roberta-base 치환

## 레시피 (최종)

- LiLT 레이아웃 흐름(lilt-infoxlm-base) + **텍스트 흐름 xlm-roberta-base 치환
  초기화**(--xlmr-init) + **gradient checkpointing OFF**(--no-checkpointing).
- 그 외 전부 LayoutXLM 정본 레시피 동일(5,000건·3에폭·배치 1·누적 16·lr 5e-5·
  8bit Adam·bf16). checkpointing OFF 는 LayoutXLM 정본(미지원으로 OFF)과 동일
  조건이므로 레시피 이탈이 아니다.
- transformers 4.57.6 / torch 2.6.0+cu124.
- 보고 표기: "LiLT(레이아웃 사전학습) + XLM-R 텍스트 초기화, LayoutXLM과 동일
  미세조정 레시피". 실패 시도 3회(InfoXLM 3에폭·10에폭, XLM-R+checkpointing)와
  원인 절연 전 과정을 병기한다(선택적 보고 금지).
- 진단용 부산물 runs_lilt\smoke·overfit_a·overfit_b·seed1(InfoXLM)·seed1_xlmr
  (checkpointing ON)은 보고 후 정리 예정(각 1GB대 - kie_lilt_seed1*.json 수치는
  보존). diag 스크립트는 임시 폴더라 보존 안 함 - 재현 절차는 이 노트가 정본.

eval_kie(정본 채점) → 중단 규칙 (ii): micro F1 < 0.80 이면 귀속 평가 생략하고
결과만 보고. ≥ 0.80 이면 kodx_eval(--skip-naopc, 어절·전체) 1시드 수행.
